# 架构与算法

桌面 Tkinter → 读取器 → 自动识别 → 单向包含匹配 → 稳定排序 → 原格式导出与审计。

`core.Table` 使用“行号 → 列号 → 值”的稀疏结构，不对格式标记的 16,384 个空列建立矩阵。XLSX 经标准 ZIP/OOXML 读取共享字符串和实际单元格；XLS 使用 xlrd。所有工作表参与候选选择，参考工作表额外依据跨表覆盖率选择。

列评分公式为 `2×唯一性 + 非空率 + 适中长度占比 + 2×字母数字形态占比 + 长数字占比 + 3×存在编号表头`，低密度列扣分。表头词包括图档编号、零件编号、零件件号、待排序项、Component Number、短文本和物料描述。识别表头不需要人工指定列。无表头表格从第一行参与处理；已识别的标题与页脚不重排。

匹配先建立参考完全值索引；来源键若无完全命中，再做 `source_key in reference_key` 的单向包含。重复来源键缓存候选列表；多候选保留全部参考行，默认使用最早参考行排序。算法对编号内容可解释，不使用语义相似度把两个不同零件猜成同一件。

排序保留所有来源业务行，每行具有原始行号、输出行号、候选参考行和状态。Python 稳定排序确保相同目标位置内不改变来源次序。默认尾部策略对匹配项排序后追加未匹配项；固定策略仅将排序后的匹配项填回原有匹配槽位。

XLSX 导出在原 ZIP 包中直接重排行 XML，单元格坐标和行号同步修改，行高、样式索引一起移动。未修改部件逐字节复制。移动区公式与跨行合并触发保护提示，不静默输出受损文件。XLS 采用合规开源读取和复制库重建值型工作簿。状态写入并列的 CSV/JSON 文件，主表保持原列结构。

核心匹配的最坏复杂度为 `O(U×R×L)`（U 为唯一来源编号数，R 为参考行数，L 为子串比较长度）；完全匹配索引平均 `O(1)`，稳定排序 `O(N log N)`。本轮千行实测覆盖从文件读取到输出，不把只测排序的时间作为完整耗时。
